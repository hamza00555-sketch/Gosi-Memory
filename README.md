# قوسي · GOSI — لعبة الذاكرة بالبطاقات المطبوعة والواقع المعزّز

لعبة ذاكرة (Memory) تُلعب **ببطاقات حقيقية مطبوعة** على الطاولة، والجوال هو الحكم:
اقلب بطاقتين، وجّه الكاميرا عليهما، فيتعرف التطبيق على البطاقات ويعرض مجسماً
ثلاثي الأبعاد فوق كل بطاقة، ويحكم بالتطابق ويحسب النقاط والأدوار ويعلن الفائز.

يعمل من المتصفح مباشرة — **بدون تحميل من المتاجر**.

## كيف يتعرف التطبيق على البطاقات؟ (التعرف الهجين)

| المسار | التقنية | الدور |
|---|---|---|
| **الصور المرجعية** | MindAR image tracking — كل وجوه بطاقات المجموعة مُجمَّعة في ملف `targets.mind` واحد | المسار الجميل: pose كامل، فالمجسم «يلتصق» بالبطاقة الفيزيائية |
| **QR احتياطي** | رمز صغير بزاوية كل بطاقة `gosi1:<الست>:<الزوج>:<a/b>` | مضمون دائماً (إضاءة سيئة/جهاز ضعيف) ويميّز نسختي الزوج |

الوجهان المتطابقان للزوج الواحد = هدف تتبع واحد، لذلك تتبع الصور لا يستطيع
التمييز بين النسختين (a/b) — طبقة الدمج `FusionResolver` تحل ذلك من حالة
اللعبة، وQR يحسمه يقيناً. أقصى تتبع متزامن بطاقتان (`maxTrack: 2`) — وهو
بالضبط ما تحتاجه لعبة الذاكرة، وأكثر من ذلك يخنق الأداء لأن TensorFlow.js
يشارك GPU مع العرض.

## المجموعات (Sets)

المحتوى «ستات» بثيمات — الست الأول: **يوم في الشاطئ** (8 أزواج: سلطعون، نخلة،
كرة شاطئ، مركب، شمس، محارة، نورس، مثلجات). يبدّل اللاعب الست من الإعدادات.

### إضافة ست جديد (بدون أي كود)

1. أنشئ مجلد `public/sets/<setId>/` فيه:
   - `set.json` — عرّف الأزواج (انسخ بنية ست الشاطئ)
   - `faces/*.svg|png` — وجوه البطاقات (**غنية بالتفاصيل والتباين** — الرسوم
     المسطحة البسيطة تتتبَّع بشكل سيئ)
   - `objects/*.glb` — المجسمات (وحدة القياس = عرض البطاقة، +Y للأعلى)
   - `sounds/*.wav` — أصوات الظهور (اختياري)
2. أضف الست إلى `public/sets/index.json`.
3. افتح **أدوات → تجميع ملامح الصور** لتوليد `targets.mind` وضعه في مجلد الست
   (أو ثبّته محلياً على الجهاز للتجربة الفورية).
4. اطبع البطاقات من **أدوات → طباعة البطاقات**.

## التشغيل والتطوير

```bash
npm install
npm run dev          # http://localhost:5173
npm test             # اختبارات المحرك وطبقة الدمج
npm run build        # فحص أنواع + بناء إنتاجي
npm run generate:assets   # إعادة توليد مجسمات/أصوات/وجوه ست الشاطئ
node scripts/verify-e2e.mjs [--compile]  # تحقق E2E في Chromium (جولة كاملة بوضع المحاكاة)
```

بدون كاميرا (كمبيوتر): شاشة اللعب توفر **وضع المحاكاة** — بطاقات افتراضية
تنقرها فتصدر نفس أحداث المسح تماماً، فتلعب الجولة كاملة.

## البنية

```
src/
├── core/                 # المحرك النقي (بلا React/IO) — قواعد اللعبة كلها
│   ├── engine/           # reduce(): flip/resolve/scores/turns/winner + اختبارات
│   └── types/            # Card, Game, Config, ids
├── recognition/          # طبقة التعرف
│   ├── QrAdapter.ts      # BarcodeDetector أو jsQR (مع إخفاء تكراري لعدة رموز)
│   ├── MindArAdapter.ts  # جسر فوق نواة MindAR Controller (وليس MindARThree)
│   ├── MockAdapter.ts    # نقر-للمسح (تطوير)
│   └── FusionResolver.ts # دمج المسارين + إسناد الجهة a/b + منع الازدواج
├── ar/stage.ts           # three.js فوق فيديو الكاميرا: pose من MindAR أو
│                         #   billboard من موقع QR (الحجم من QR_FRACTION)
├── features/             # الشاشات: home, game(AR), results, settings, tools
├── lib/                  # sets loader/codec, cardFace, printLayout, audio, platform
└── i18n/                 # عربي/إنجليزي + RTL تلقائي
scripts/                  # توليد الأصول + التحقق E2E
public/sets/beach-day/    # ست الشاطئ الكامل
```

**قاعدة ذهبية:** كل قواعد اللعبة في `core/engine` النقي المُختبَر — الواجهة
والتعرف لا يقرران شيئاً، فقط يحوّلان المسح إلى أفعال `SELECT_CARD`.

## فخاخ المنصات المطبقة (خلاصة تجارب مؤلمة)

- **أذونات iOS** تُطلب داخل ضغطة المستخدم **وقبل أي `await`** (فتح الصوت أول
  سطر في زر «ابدأ الكاميرا»).
- **الصوت عبر WebAudio**: `AudioContext.resume()` مرة واحدة داخل الضغطة، ثم أي
  صوت لاحق مسموح — يرضي سياسات autoplay كلها.
- **متصفحات داخل التطبيقات** (واتساب/انستغرام) تحجب الكاميرا — تُكشف من UA
  وتظهر رسالة «افتح في Safari/Chrome» قبل الإحباط.
- **الأداء مع التتبع**: مسح QR على canvas مصغّر ≤640px بمعدل ≤7fps،
  و`pixelRatio ≤ 1.5` للعرض — المتتبِّع يشارك GPU.
- **سباق المسح المتزامن**: رمزان في لقطة واحدة يصلان في نفس الإطار — مرجع
  الحالة يُحدَّث فورياً (متزامناً) لا عبر إعادة رسم React.
- **المسح أثناء نافذة النتيجة**: يُخزَّن في طابور ويُعاد تطبيقه بعد انتهائها
  (التتبع لا يعيد إطلاق `found`).

## الاختبار على جوال حقيقي (لا بديل عنه)

1. انشر (Vercel) أو شغّل `npm run dev -- --host` وافتح من الجوال (يتطلب HTTPS
   للكاميرا — استخدم النشر أو نفقاً).
2. اطبع ورقة البطاقات (أو اعرضها على شاشة ثانية للتجربة).
3. ابدأ جولة، اقلب بطاقتين، وجّه الكاميرا: يجب أن يظهر المجسمان ويصدر الحكم.
4. جرّب: إضاءة منخفضة (يجب أن يستمر QR)، بطاقتين بعيدتين (مسح واحدة تلو
   الأخرى)، والقلب السريع أثناء ظهور النتيجة.

## الترخيص والأصول

كل الأصول (مجسمات GLB، أصوات WAV، رسوم الوجوه SVG) **مولّدة برمجياً** داخل
المشروع (`scripts/generate-*.mjs`) — لا حقوق نشر لطرف ثالث.
